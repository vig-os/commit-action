Corrects the unreleased **Adopt vigOS devkit 1.6.0** entry, which describes a

## Changes Made

The 1.6.0 bullet ended with:

> …the dev shell reports the gap as a vig-os/devkit#1263 skew warning on load.

True when written — the adoption (#124) was a pin-only edit that left the
floating `vigos` input locked at `26e291d`, the 1.5.1 release, so the dev shell
ran the 1.5.1 toolchain under the 1.6.0 scaffold. #126 then advanced
`flake.lock` to `ffa7a5f`, the 1.6.0 release commit, and the warning stopped
firing. That PR carried no changelog entry of its own, so the lock movement was
unrecorded while the stale claim survived.

This drops the skew sentence and adds a sub-bullet recording the pin advance,
ending on the state the release actually ships: pin and scaffold in lockstep.

## Changelog Entry

This PR *is* the changelog change. The amended sub-bullet:

  - **The flake pin was advanced to match** ([#126](https://github.com/vig-os/commit-action/pull/126)). The adoption above was a pin-only edit, which left the floating `vigos` input locked at `26e291d` (the 1.5.1 release): the dev shell ran the 1.5.1 toolchain under the 1.6.0 scaffold, and the shell-entry version-skew warning (vig-os/devkit#1263) fired on every entry. `nix flake update vigos` advanced the lock to `ffa7a5f`, the 1.6.0 release commit. The 1.6.0 shell builds, the full hook suite is green, and the warning is gone — so this release ships with pin and scaffold in lockstep.
