# [PR 132](https://github.com/vig-os/commit-action/pull/132) build(dist): rebuild the committed bundle and correct the lock-file changelog entry

## Description

Rebuilds the committed action bundle, which had drifted from `src/` plus the
current `package-lock.json`, and corrects the changelog entry that
mis-described the drift's cause as harmless.

Found while preparing the v0.3.2 release: the release PR would have failed its
required `Dist Check` gate.

## Type of Change

- [x] `build` -- Build system or dependency changes
- [x] `docs` -- Documentation only

### Modifiers

- [ ] Breaking change (`!`)

## Changes Made

**`dist/index.js` rebuilt** (`just sync && just bundle`), +146 / -15. The diff is
entirely inlined dependency code — `src/` is untouched, and has been since
`v0.3.1`. Two movements reach the bundle:

| Dependency | Movement | Reaches the bundle via | From |
| --- | --- | --- | --- |
| `undici` | `6.27.0` → `6.28.0` | `@actions/core` → `@actions/http-client`, and `@actions/github` | #109, #116, #120 |
| `@octokit/request` | `10.0.11` → `10.0.13` | `@actions/github` | #129 |
| `@octokit/core` | `7.0.6` → `7.0.7` | `@actions/github` | #129 |

The `undici` delta is request-path hardening: header-value validation before
coercion (rejecting values produced by a crafted `toString` /
`Symbol.toPrimitive`, and an invalid `content-type` derived from a blob body),
plus `Content-Length`-mismatch detection on partial/ranged responses.

**Only `dist/index.js` is committed.** The `dist/src/**` declaration byproducts
are gitignored, yet still tracked from the `v0.3.0` finalize commit (the
vig-os/devkit#1159 force-add bug, since fixed upstream), and they embed an
absolute `sourceRoot` of `/home/runner/work/commit-action/commit-action`. A
locally built copy rewrites that to the developer's home path and would make
CI's `Dist Check` rebuild diff and fail. They were explicitly restored before
staging.

**Changelog**: corrected the lock-file-maintenance bullet, which asserted
*"Transitive dev-dependency movement only"* — false, as the table above shows;
folded in #129, which had no entry at all; and added the `Fixed` entry.

## Changelog Entry

### Fixed

- **The committed action bundle is rebuilt and back in sync with its lock file** ([#130](https://github.com/vig-os/commit-action/issues/130)). `dist/index.js` — the artifact `action.yml` actually runs, and therefore the only thing consumers of a released tag execute — still inlined dependency versions the lock file had moved past. Nothing rebundled after the lock-file maintenance PRs, and `dist-check.yml` triggers only on pull requests to `release/**` and `main` while every dependency PR targets `dev`, so the drift accumulated unseen. The refreshed bundle carries `undici` `6.28.0` (header-value validation before coercion, rejecting values produced by a crafted `toString`/`Symbol.toPrimitive` and an invalid `content-type` derived from a blob body, plus `Content-Length`-mismatch detection on partial responses) and `@octokit/request` `10.0.13` / `@octokit/core` `7.0.7`.

Plus the correction to the existing `Changed` bullet (see diff).

## Additional Notes

Two follow-ups this uncovered, both deliberately out of scope:

1. `dist-check.yml` never runs on `dev`, which is exactly why this went unseen.
   Its trigger is devkit-managed, so widening it needs an upstream change.
2. `dist/src/**` should not be tracked at all (it is already gitignored) —
   `git rm --cached dist/src` would end the absolute-path hazard permanently.
