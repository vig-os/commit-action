# Release 0.3.3

This PR prepares release 0.3.3 for merge to main.

## [0.3.3] - TBD

### Changed

- **The release pipeline rebuilds the action bundle instead of relying on a hand-written commit** ([#157](https://github.com/vig-os/commit-action/issues/157)). `prepare-release-extension.yml` — the devkit-seeded, consumer-owned no-op whose header names exactly this use case — now resolves the devkit toolchain, runs `just sync && just bundle` on the freshly cut `release/X.Y.Z`, and commits `dist/` when it differs. It runs after the branch is fast-forwarded onto the changelog freeze and before `open-pr`, so the refreshed bundle is in the release PR diff from its first CI run and `Dist Check` validates it; `rollback` already lists `extension` in its `needs`, so a failed rebuild deletes the branch and takes the commit with it. `release-extension.yml`'s finalize-time `verify-dist` is untouched and becomes a genuine backstop rather than the only gate, and `dist-check.yml` triggers are unchanged so `dev` stays ungated ([#71](https://github.com/vig-os/commit-action/issues/71)). This removes the recurring manual rebuild that [#130](https://github.com/vig-os/commit-action/issues/130) fixed once by hand and that had accrued again: six lock-file-maintenance PRs ([#139](https://github.com/vig-os/commit-action/pull/139), [#143](https://github.com/vig-os/commit-action/pull/143), [#146](https://github.com/vig-os/commit-action/pull/146), [#148](https://github.com/vig-os/commit-action/pull/148), [#152](https://github.com/vig-os/commit-action/pull/152), [#156](https://github.com/vig-os/commit-action/pull/156)) moved `@octokit/core`, `@octokit/request`, `@octokit/endpoint`, `@octokit/request-error`, `@octokit/graphql`, `content-type` and `undici` — all **runtime** transitives that `ncc` inlines — while the committed bundle stood still. Drift is read from `git status` rather than a walk of `dist/`, so the gitignored declaration byproducts under `dist/src/` stay untracked (the vig-os/devkit#1159 bug behind [#134](https://github.com/vig-os/commit-action/issues/134)), and the commit is made through `vig-os/commit-action` at its last released tag rather than the possibly-stale local bundle.
