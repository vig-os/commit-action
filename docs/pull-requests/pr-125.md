# [PR 125](https://github.com/vig-os/commit-action/pull/125) docs(changelog): document devkit 1.4.1, 1.4.2 and 1.6.0 adoptions

Changelog-only. `## Unreleased` stopped at devkit 1.4.0 while `.vig-os` had advanced to `DEVKIT_VERSION=1.6.0`, leaving six merged PRs undocumented.

## Added entries

- **devkit 1.4.1** (#110) — RC train rc2 → rc4 → final; scaffold diff vs 1.4.0 is pin-only plus the label-taxonomy header and the `DEVKIT_SYNC_*` knobs.
- **devkit 1.4.2** (#117) — security-register patch; first consumer to exercise the vig-os/devkit#1263 pin-lockstep fix.
- **devkit 1.6.0** (#121, #124) — `devkit-upgrade.yml`, the scaffold-drift CI gate, the new `.vig-os` keys (all left empty), the Renovate preset exclusion and `release-publish.yml` tombstone detection. Notes that this lane jumped **1.4.2 → 1.6.0 directly**: 1.5.0 was never finalized on consumers, so #122 was closed as stale rather than merged.
- **Lock file maintenance** (#109, #116, #120) — consolidated. Transitive-only: `package.json` is untouched by all three and no direct dependency range changed.

## Corrected entries

Two entries claimed the `vigos` flake `?ref` pin moved in lockstep with the scaffold. That was true only through the RC trains — the pin was deliberately returned to the scaffold's floating default at 1.4.0 final (`86a14d6`), those RC pins having been validation-only.

The 1.6.0 entry now records the actual state: the input is still floating, which is what produces the vig-os/devkit#1263 skew warning on shell load (`.vig-os` at 1.6.0, the flake resolving whatever devkit `main` is). Whether to pin it again is a separate decision and deliberately not part of this PR.
