# [PR 135](https://github.com/vig-os/commit-action/pull/135) chore(dist): untrack the gitignored dist/src byproducts

Closes #134.

## What

`git rm -r --cached dist/src` — 12 declaration byproducts stop being tracked. They stay on disk, stay gitignored (`.gitignore` line 51), and are regenerated by `just bundle`, as [#70](https://github.com/vig-os/commit-action/issues/70) intended.

## Why

`dist-check.yml` and `release-extension.yml` both document, in their headers, that `dist/src/` is gitignored and `dist/index.js` is the only tracked path under `dist/` — which is what makes their tree-wide `git status -- dist/` check "deterministic across checkout locations".

That invariant was false. The v0.3.0 finalize commit (`1260b1d`) re-added the byproducts via vig-os/devkit#1159, in which the release step walked a bare `dist` directory path and force-added every file it found without consulting `.gitignore`. devkit fixed that upstream — `release-core.yml` now derives its paths from `git ls-files -co --exclude-standard` — but the residue here was never cleaned up.

Each `.d.ts.map` embeds an absolute `sourceRoot`:

```json
"sources":["file:///home/runner/work/commit-action/commit-action/src/retry.ts"]
```

So the check passed only because CI happens to rebuild at the same absolute path that was committed. Any other checkout location reported six modified files. That is what forced the hand-staging of `dist/index.js` in #132 — committing a locally built tree would have written developer-machine paths into the repo.

## Verified

| Assertion | Result |
| --- | --- |
| `git ls-files dist/` | `dist/index.js`, `dist/package.json` only |
| `just sync && just bundle` then `git status --porcelain -- dist/` | **empty** on a developer machine — first time this has been true |
| `release-core.yml` `DIST_PATHS` (`git ls-files -co --exclude-standard -- dist`) | `dist/index.js,dist/package.json` — non-empty, no-files guard still holds |
| `prek run --all-files` | green |

Both release gates get stronger, not weaker: `dist-check.yml`'s `git status --porcelain` does not report untracked-and-ignored files, so it stays clean in CI and becomes honest everywhere else, and the finalize commit stops writing runner paths into every release tag.

## Consumer impact

None. `action.yml` runs `dist/index.js`, which stays tracked. The `.d.ts` declarations are build byproducts with no runtime role.

Sequenced deliberately before the v0.3.2 release: deferring means the finalize commit re-commits the `/home/runner` paths into the v0.3.2 tag.
